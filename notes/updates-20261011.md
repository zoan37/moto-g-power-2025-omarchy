# Keeping the phone safe across `pacman -Syu` (2026-10-11)

What an Arch upgrade can and can't touch here:

| Piece | Where | Upgrade risk |
|---|---|---|
| Patched Mesa (panfrost-kbase), libmali | `/opt/vegas-gpu/*`, loaded via `LD_LIBRARY_PATH` by the desktop launcher and the Chrome wrapper | none (not package-owned). The system `mesa` package isn't used by the desktop or Chrome; `pacman -Qkk mesa` shows only mtime changes |
| Hyprland 0.56 + patched aquamarine | `/opt/omarchy-android/{hyprland,aquamarine}` (pinned bundle) | **was high**: it linked system `libhyprutils.so.13`, `libhyprlang.so.2`, `libhyprgraphics.so.4`, `libre2.so.11` (+ abseil), `libdisplay-info.so.3`, … which Arch bumps often. Now pinned (below) |
| Omarchy shell/scripts | `/usr/share/omarchy` (bundle copy, not package-owned) | none from pacman; phone patches re-apply idempotently (`omarchy-patches`) |
| Kernel, vendor modules, firmware | boot partitions, `/opt/vegas-*`, `/usr/lib/firmware` copies | none (no `linux` package installed) |
| Phone glue | `/usr/local/*` | none |
| quickshell + Qt 6 | packages (ALARM extra) | **held** (`vegas-pacman-holds`): the pinned shell bundle targets quickshell 0.3 |
| systemd, PipeWire, BlueZ, Chrome, everything else | packages | normal Arch upgrades |

## Pinning the Hyprland bundle

`vegas-pin-desktop-libs apply` copies every library the bundle (Hyprland, hyprctl, hyprpm, libaquamarine) resolves
from `/usr/lib` into `/opt/omarchy-android/pinned-libs` (158 libraries, 104 MB). It then sets the bundle's RUNPATH
there, and `$ORIGIN` on the pinned copies. These stay system-wide:
- glibc, libstdc++/libgcc_s/libgomp (must match ld.so)
- udev/systemd (talk to the running daemons)
- the GL/Vulkan dispatch libraries (must match the GPU stack in /opt and the Vulkan manifests)

Running binaries are patched as a copy and renamed over ("Text file busy" otherwise). A backup of the original
binaries is at `/var/lib/vegas/omarchy-android-bins-before-pin.tgz`.

Verified: after a reboot, Hyprland maps `pinned-libs/libhyprutils.so.13` and 795 mappings come from the pinned
dir; vegas-doctor 0/0. vegas-doctor warns if the RUNPATH is missing (e.g. after the bundle is reinstalled). Run
`vegas-pin-desktop-libs apply` **before** the next system upgrade in that case, while the old libraries still exist.
`vegas-pin-desktop-libs check` lists where each bundle binary loads its libraries from.

## Holding the shell runtime

The Omarchy shell bundle is written for quickshell 0.3.x, and a quickshell release with breaking changes would
leave the phone without its status bar, nav bar and home screen. quickshell uses Qt's private API, so Arch rebuilds
it with every Qt update: it can't be held alone. `vegas-pacman-holds apply` adds `IgnorePkg = quickshell qt6-*` (with
a marker comment) to `/etc/pacman.conf`. Nothing else on the phone depends on Qt 6 (`Required By` of every qt6-*
package is only quickshell), so the hold blocks no other upgrade. `remove` undoes it; update quickshell and the
Omarchy bundle together, deliberately. vegas-doctor reports the hold.

## Before upgrading: refresh the rescue copy

There is no package rollback: Omarchy's `package-cleanup.hook` runs `rm -rf /var/cache/pacman/pkg` after every
transaction, and Arch Linux ARM keeps no archive of old versions. The fallback is the microSD **rescue copy**
(`/omarchy` on the card's ext4 `vegas-arch`). The ramdisk boots it, with the red SD badge, when the internal root
fails. `vegas-rescue-sync` mirrors the running internal root onto it (`rsync -aHAXx --delete`, without
/proc /sys /dev /run /tmp /mnt, caches or the journal; it checks free space and stamps `/var/lib/vegas/rescue-synced`).
The microSD is slow with many small files: the first full refresh (7.3 GB; the old copy was from 2026-10-10)
takes well over 10 minutes.

Upgrade procedure:
1. `vegas-rescue-sync`
2. `pacman -Syu` (quickshell/Qt held; the Hyprland bundle pinned)
3. reboot
4. `vegas-doctor`

An unconfirmed systemd boot falls back to native-init by itself (ramdisk `systemd-pending`), and a failed internal
boot falls back to the card.

## First full upgrade (2026-10-11, 14:20–14:28)

- `vegas-rescue-sync`: 20 min, 1.19 GB sent (the old copy was mostly identical), done 14:20.
- `pacman -Su`: 166 → 154 packages upgraded (12 held: quickshell 0.3.1→0.3.2 and Qt 6.11.2→6.12.0). Among them:
  systemd 261.2→262, PipeWire 1.6.8→1.6.9, WirePlumber 0.5.15→0.5.18, libinput 1.31→1.32, the system
  hyprland/aquamarine/hyprutils (unused; the bundle is pinned), mesa (unused by the desktop and Chrome).
- The one `error:` in the log is the udev hook's `change` trigger, rejected by two MediaTek power-supply nodes
  (`cp-standalone`, `mtk-gauge`): harmless.
- After a reboot: systemd 262 is `running` with no failed units, startup 8.6 s, and vegas-doctor 0 FAIL / 0 WARN
  (desktop, audio, Bluetooth, sensors, haptics, autosleep, video decode).
