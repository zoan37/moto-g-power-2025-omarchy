# Rebuilding the stock boot kernel (2026-10-10)

Steps 1–2 of `notes/handoff-kernel-20261010.md`. The phone was not touched. The builds ran on an x86_64 host with
Google's prebuilt clang (about 10 minutes each at `-j14`, including the full-LTO link). No boot image was built or
flashed.

## Result

- The stock `boot` kernel is **Google's GKI build, not a Motorola build**: `ab13743836` on branch
  `aosp_kernel-common-android13-5.15-2025-05`, kernel/common `46a5565a09828fa71fd2e715c98f8100e3c15ee3`. The
  `Image` in `boot.stock.img` (gzip payload) is byte-identical to that build's `Image` artifact.
- Rebuilt from source: **byte-identical `Image`** (sha256 `d47d9d63…51c8b`), byte-identical `.config` (the same as
  `artifacts/vegas-linux-bringup/stock-kernel.config`, comments included), byte-identical `vmlinux.symvers`.
  The banner is identical, including `-00021-g46a5565a0982-ab13743836`, `#1 SMP PREEMPT Mon Jul 7 16:28:30 UTC 2025`
  and the compiler string.
- **Tier 1** (`DEVTMPFS`, `DEVTMPFS_MOUNT`, `FHANDLE`, `AUTOFS_FS`, all `=y`): `Module.symvers` is
  byte-identical to stock, so every CRC is unchanged. Same `uname -r`; `uname -v` is `#2`, and
  `/proc/version` names `build-user@vegas-tier1`.
- Vendor module CRCs (`vendor_boot` 197 + `vendor_dlkm` 195 + 2 diagnostic `.ko` = 394 files, 371 distinct):

  | Kernel | Imported symbols that the kernel exports | Match | Mismatch | Missing |
  |---|---|---|---|---|
  | Google `vmlinux.symvers` (reference) | 2345 | 2345 | 0 | 0 |
  | Rebuilt stock `Module.symvers` | 2355 | 2355 | 0 | 0 |
  | Tier 1 `Module.symvers` | 2355 | 2355 | 0 | 0 |

  Of the 3954 unique imported symbols, the other 1599 are exported by other vendor modules. The 10 extra in the
  rebuilt rows are the `zs_*` exports of the GKI `zsmalloc.ko`, which is built by `make modules`; `vendor_boot`
  ships its own `zram.ko`/`zsmalloc.ko`. No two vendor modules disagree on a CRC.

## How the stock kernel is built

- `BUILD_INFO` of ab13743836: `BUILD_CONFIG=common/build.config.gki.aarch64 build/build.sh` (legacy build.sh, not
  Kleaf), kernel/build `b05fb2e75ba8`. Config chain: `gki_defconfig` → `check_defconfig` (savedefconfig must equal
  it) → `TRIM_NONLISTED_KMI=1`: `build/abi/process_symbols` merges `android/abi_gki_aarch64` and 36 more lists
  (`ADDITIONAL_KMI_SYMBOL_LISTS`) into `abi_symbollist` (identical to Google's artifact), flattened to
  `abi_symbollist.raw` = `CONFIG_UNUSED_KSYMS_WHITELIST` → `olddefconfig`.
- Toolchain: `build.config.constants` `CLANG_VERSION=r450784e` → "Android (8508608, based on r450784e) clang
  version 14.0.7 (… llvm-project 4c603efb0cca…)", the same string as `CONFIG_CC_VERSION_TEXT`. The pahole in
  kernel/prebuilts/build-tools is v1.23, which matches `CONFIG_PAHOLE_VERSION=123`.
- Environment: `LLVM=1 ARCH=arm64`, `KCFLAGS=-D__ANDROID_COMMON_KERNEL__`, `SOURCE_DATE_EPOCH` = commit time,
  `KBUILD_BUILD_USER/HOST=build-user/build-host`, NDK r23 sysroot in `USERCFLAGS` (needed for
  `CC_CAN_LINK=y`), `-ffile-prefix-map`, `BUILD_NUMBER=13743836` (gives `-ab13743836`).
- The stock config embeds Google's build path (`CONFIG_UNUSED_KSYMS_WHITELIST="/mnt/disks/build-disk/…"`), and
  `IKCONFIG` puts it into the Image. The script bind-mounts `third_party/kernel/gki-root` on `/mnt` inside
  `unshare --map-root-user --mount` (no root), so the tree sits at the original path.
- Byte identity also needs Google's hermetic `gzip` (toybox 0.8.7) and `xz` 5.2.5 from platform/prebuilts/build-tools
  `f6813860e16b`. With the host's gzip/xz, only the `IKCONFIG`/`IKHEADERS` blobs differ, which shifts every later
  address. Symvers and CRCs are unaffected either way.
- `git describe` needs tags that the shallow clone lacks, so the script writes `.scmversion` =
  `-android13-8-00021-g46a5565a0982`.
- Module signing: the stock Image embeds an ephemeral "Build time autogenerated kernel key" whose private key is gone.
  The script cuts that certificate out of the stock Image (`__module_cert_start`…`__module_cert_end`, 1357 bytes,
  SHA-256 fingerprint `0F:42:56:6D:…:46:5C`) and uses it as `certs/signing_key.pem`. This allows byte identity, and
  stock-signed GKI modules still verify. `make Image modules` doesn't sign anything; `modules_install` would fail
  for lack of a private key, and isn't needed.

### Motorola's tree (kernel-mtk) is for the vendor modules, not `boot`

`MotorolaMobilityLLC/kernel-mtk` tag `android-16-release-w1ve36h.10-12r3` (HEAD "Merge … GKI
android13-5.15-2025-05_r6") has MTK and Motorola patches in core files (`kernel/printk`, `kernel/sched`, `mm/slub.c`,
`mm/memory.c`, `include/linux/printk.h`, … 1367 differing or extra paths against `46a5565a0982`). It builds the
vendor modules (vermagic `5.15.180-android13-8-gd63125a6a58d`) from `gki_defconfig` + `mgk_64_k515_defconfig` +
`ext_config/moto-mgk_64_k515.config` + `moto-mgk_64_k515-vegas.config` (the latter is identical to
`artifacts/battery-research/…`; `debug-*`/`-df` fragments are added for non-user and non-production builds, per
`defconfig.mk`). That tree with `gki_defconfig` would **not** reproduce the boot kernel. Use AOSP kernel/common at
the GKI commit.

## Module loading on a rebuilt kernel

- Vendor modules are **unsigned** (0 of 394 have a signature; `mgk_64_k515_defconfig` sets
  `# CONFIG_MODULE_SIG_ALL is not set`). Stock already loads them unsigned.
- `CONFIG_MODULE_SIG=y`, `# CONFIG_MODULE_SIG_FORCE is not set`, `CONFIG_MODULE_SIG_PROTECT=y`. With
  PROTECT, `module_sig_check` returns 0 for unsigned modules. They can't use symbols in
  `android/abi_gki_modules_protected` or re-export `android/abi_gki_modules_exports`, but **both lists are empty at
  this commit**, so the restriction is a no-op. A new signing key wouldn't block anything; reusing the stock certificate
  avoids even the GKI-signed `zram.ko`/`zsmalloc.ko` being treated as unsigned.
- vermagic: modversions kernels compare vermagic only after the release string (`same_magic`), so the Motorola
  release string on the modules doesn't matter (it doesn't on stock either). `module_layout` CRC matches.
- CFI (`CFI_CLANG`, `CFI_CLANG_SHADOW`, not permissive): type IDs come from function type names, with the same
  compiler. Tier 1 changes no exported prototype (`Module.symvers` identical), so CFI is not a concern.

## Reproduce

Downloads (into `third_party/kernel/`, gitignored):

```sh
cd third_party/kernel
R=gki-root/disks/build-disk/src/android/common-android13-5.15-2025-05
G=https://android.googlesource.com
# reference artifacts of the stock build (vmlinux.symvers, Image, System.map, abi_symbollist, BUILD_INFO, boot.img, ...)
curl -L -o gki-ab13743836/vmlinux.symvers \
  "https://androidbuildinternal.googleapis.com/android/internal/build/v3/builds/13743836/kernel_aarch64/attempts/latest/artifacts/vmlinux.symvers/url"
# source and prebuilts at the revisions in manifest_13743836.xml
git init $R/common && git -C $R/common fetch --depth 1 $G/kernel/common 46a5565a09828fa71fd2e715c98f8100e3c15ee3 && git -C $R/common checkout FETCH_HEAD
curl -L $G/platform/prebuilts/clang/host/linux-x86/+archive/9f759dee5cdc5f85d076c642a192f6a9232f7058/clang-r450784e.tar.gz | tar -xz -C $R/prebuilts/clang/host/linux-x86/clang-r450784e
curl -L $G/kernel/prebuilts/build-tools/+archive/083e34d8c2c4239be4967172427268c267585951/linux-x86.tar.gz | tar -xz -C $R/prebuilts/kernel-build-tools/linux-x86
curl -L $G/toolchain/prebuilts/ndk/r23/+archive/93532f3052c14fbb337ff57d5732128dc7481ee6/toolchains/llvm/prebuilt/linux-x86_64/sysroot.tar.gz | tar -xz -C $R/prebuilts/ndk-r23/toolchains/llvm/prebuilt/linux-x86_64/sysroot
curl -L $G/kernel/build/+archive/b05fb2e75ba86f934da7fbcb4435678a54645c5f.tar.gz | tar -xz -C $R/build/kernel
# optional, for a byte-identical Image: hermetic gzip/xz/cpio (+ their libs)
for d in linux-x86/bin linux-x86/lib64 path/linux-x86; do
  curl -L $G/platform/prebuilts/build-tools/+archive/f6813860e16b2fa1461a15e7b8a3127dfdee021a/$d.tar.gz | tar -xz -C $R/prebuilts/build-tools/$d
done
ln -s $R gki-src
```

(Create the target directories first with `mkdir -p`.) SHA-256 of the archives: clang `0e350235…ecbc`,
kernel-build-tools `c9a9bd47…2772`, NDK sysroot `21d6298a…85f0`, kernel/build `222aa800…c722`, build-tools bin
`0d49aaae…8de0`, lib64 `b53b9a71…d4de3`, path `554ca1e3…e2e1`. The stock certificate goes in
`third_party/kernel/gki-ab13743836/gki-module-signing-cert.pem`. To cut it from the stock Image: offset =
`__module_cert_start` − `_text` from `System.map`, length 1357, then `openssl x509 -inform DER -out …pem`.

## Repacking `boot` (not done yet)

`boot.stock.img`: header v4, kernel = gzip'd Image (21516990 bytes), no ramdisk, empty cmdline, os_version and patch
level 0 in the header. AVB hash footer, algorithm NONE, partition 64 MiB, props `com.android.build.boot.os_version=13`,
`…fingerprint=motorola/vegas_g_hal/vegas:13/W1VES36H.10-12-1/89dab7:user/release-keys`, `…security_patch=2024-05-05`
(listed twice). `vbmeta.stock.img` holds the boot hash, so a new kernel only boots in the unlocked (orange) state,
which this unit is in. Tools: `mkbootimg`, `unpack_bootimg`, `avbtool` from the host's android-tools.

```sh
gzip -9n -c Image > Image.gz
mkbootimg --header_version 4 --kernel Image.gz --cmdline '' --output boot.tier1.img
avbtool add_hash_footer --image boot.tier1.img --partition_name boot --partition_size 67108864 --algorithm NONE \
  --prop com.android.build.boot.os_version:13 \
  --prop com.android.build.boot.fingerprint:motorola/vegas_g_hal/vegas:13/W1VES36H.10-12-1/89dab7:user/release-keys \
  --prop com.android.build.boot.security_patch:2024-05-05
unpack_bootimg --boot_img boot.tier1.img && avbtool info_image --image boot.tier1.img   # check before any flash
```

## On the phone (2026-10-11, night): tier 1 runs

- **Tier 1 boots and everything works.** `uname -v` shows `#2`, `/proc/filesystems` has devtmpfs and autofs,
  all 224 modules load (no CRC/symbol errors), and `vegas-doctor` reports 0 FAIL, 0 WARN (GPU, video decode, Wi-Fi,
  fuel gauge, boost daemon). boot_b now holds `boot.tier1-raw.img`: `mkbootimg --header_version 4 --kernel
  Image.tier1.gz --cmdline ''`, **no AVB footer needed** (the unlocked LK boots it).
- **Safety net for kernel tests:** `fastboot oem fb_mode_set` makes every boot stop in fastboot ("UTAG bootmode
  configured as fastboot"); `fastboot continue` boots once, and a failed boot returns to fastboot. `fastboot oem
  fb_mode_clear` restores normal boots. **Clear it after testing.**
- **fastboot gotchas:** after `continue`, LK keeps its fastboot USB id (22b8:2e80) for ~14 s before handing off. A second
  `continue` in that window aborts the boot and leaves the phone in fastboot. The first command right after arriving
  in fastboot sometimes fails (`FAILED (remote: '')`, or a USB drop mid-write); retrying works.
- fastboot accepts our custom images for both boot_b and init_boot_b (and Motorola's signed ones). Recovery never
  needs Android; never flash the stock init_boot: Android would try to mount `userdata`, which holds the Omarchy root.
- Writing boot_b from Linux with `dd` also works.
- Repacking with avbtool's footer isn't needed. The stock image's compressed kernel is ~15 KB smaller than gzip -9
  manages (Google's build uses a different deflate encoder), so a stock-layout splice doesn't fit.
