## Summary

- **No sound card on the phone today.** `/proc/asound/cards`: `--- no soundcards ---`; `/dev/snd` has only `timer`.
  ALSA core and ASoC are built into the stock GKI kernel (`snd`, `snd_pcm`, `snd_soc_core`; `snd_usb_audio` too).
  None of the vendor audio modules are loaded: the native init only loads vendor_boot modules, and the Wi-Fi/GPU
  helpers load only their own vendor_dlkm modules.
- **Hardware** (vendor files + live DT + I2C):
  - SoC AFE `mt6835-afe-pcm@11050000` (`mediatek,mt6835-sound`), machine driver `mediatek,mt6835-mt6377-sound`,
    card name `mt6835-mt6377` (ALSA id `mt6835mt6377`, as in `audio_device.xml` `<card name="mt6835mt6377"/>`).
  - Codec: the MT6377 PMIC's audio part (`mt6377codec`, `mediatek,mt6377-sound`): headphone amp, ADCs, mic bias.
    3.5 mm jack detection is MT6377 accdet (DT `accdet`, `status okay`, 4-key headset thresholds).
  - **Three Awinic smart amps on I2C bus 6, all on one I2S3 link** (I2S0 is their feedback/echo-ref input):
    `6-0034` (`sound-channel 0`, aw_dev_0, AW88394), `6-0035` (channel 1, aw_dev_1, AW88394), `6-0037`
    (channel 2, aw_dev_2, AW88166). DT `sound` node: `mediatek,spk-i2s = <3 0>` (out I2S3, in I2S0),
    `mediatek,speaker-codec` = @34 + @35, `smartpa-hac-flag = <1>`.
  - The earpiece is not a separate analog path: aw_dev_0 (top) switches to its "Receiver" profile and aw_dev_1 is
    switched off. In music both amps play (stereo speakers).
  - Mics: analog (DT `mediatek,mic-type = <1 1 1>` = ACC, `dmic-mode = <0>`): main mic AIN0 (bottom), second mic
    AIN2 (back), headset mic AIN1. `MTK_AUDIO_NUMBER_OF_MIC=2`.
- **No Android HAL, SCP or ADSP needed for plain playback/capture.** `MTK_AUDIODSP_SUPPORT=no`; DT
  `snd_scp_audio` has `scp-spk-process-enable = <0 ...>` (SCP speaker processing off by default). Speaker
  protection runs inside the AW88394s (on-chip DSP, `have_dsp=1`), configured by the kernel driver from
  `aw883xx_acf.bin`. What Linux loses (tuning, not function): MTK BesLoudness and Awinic "SKTune" in the HAL's
  aurisys downlink (`aurisys_config.xml`), the per-unit speaker calibration (`cali_re`), and Motorola's volume ramp
  (`audio_ext_spkr.conf`). The SCP and ADSP modules are still needed **as symbol dependencies** of the machine driver.
- Deliverables: UCM2 draft `port/vegas/root/usr/share/alsa/ucm2/` (conf.d link + `MediaTek/mt6835/mt6377-aw88394/`),
  test script `scripts/test-vegas-audio.sh`, extracted vendor files under `artifacts/audio/` (gitignored).

`snd-soc-mt6377` · `mt6835-mt6377`.

15 modules to load (copies staged in `artifacts/audio/stage/opt/vegas-audio/modules/`, with `SHA256SUMS`). Why
each matters:

- The card binds only when **every** DAI link resolves:
  - the three aw883xx DAIs on I2S0/I2S3 (with `smartpa-hac-flag = 1` the probe swaps in the 3-codec "hasHAC"
    lists, so `6-0037` must probe too)
  - `18050000.mtk-btcvsd-snd` (BTCVSD link, `mtk-btcvsd.ko`; the DT device exists)
  - the MT6377 VOW DAI (in `snd-soc-mt6377`)
  - `snd_scp_audio` (SCP_SPK_Process link, `mtk-scp-audio`; its probe doesn't wait for the SCP)
- `scp.ko` has never been loaded under Linux here. The SCP image itself is loaded by LK (reserved memory
  `mblock-27-SCP-reserved` exists; the driver has no `request_firmware`). It's the riskiest insmod: watch dmesg for
  AEE/watchdog messages.
- `snd-soc-aw883xx` requests `aw883xx_acf.bin` **synchronously at codec probe** (`sync-load = <1>`), 3 tries with 1 s
  in between. The kernel command line has `firmware_class.path=/vendor/firmware`, which doesn't exist on the
  rootfs, so the file has to go in `/usr/lib/firmware/` (the fallback path). Without it the amps never power up and
  the `aw_dev_*` controls (created only after the firmware parses) don't exist.
- vermagic `5.15.180-android13-8-gd63125a6a58d`, the same as the Wi-Fi/GPU vendor_dlkm modules that already load
  (see `notes/kernel-build-20261010.md`).

## Card layout (from the machine driver, to verify with `/proc/asound/pcm`)

PCM device = DAI link index. Front ends: `Playback_1`=0, `Playback_12`=1, `Playback_2`=2, `Playback_3`=3 (deep
buffer) … `Playback_9`=9, `Capture_1`=10 … `Capture_9`=18, `Capture_Mono_1..3`=19–21, then hostless links. The PCM
ids are `"<name> (*)"`; the UCM and the test script look PCMs up by name.

Controls used (all names checked in the source):

| Block | Controls |
|---|---|
| AFE interconnect (DAPM mixers) | `I2S3_CH1 DL1_CH1`, `I2S3_CH2 DL1_CH2`, `ADDA_DL_CH1 DL2_CH1`, `ADDA_DL_CH2 DL2_CH2`, `UL1_CH1 ADDA_UL_CH1`, `UL1_CH2 ADDA_UL_CH2` |
| AFE | `I2S3_HD_Mux` (Normal/Low_Jitter), `ADDA_UL_Mux` (MTKAIF/AP_DMIC) |
| MT6377 | `DAC In Mux`, `HPL Mux`, `HPR Mux`, `LOL Mux`, `RCV Mux`, `MISO0/1/2_MUX`, `ADC_L_Mux`, `ADC_R_Mux`, `PGA_L_Mux`, `PGA_R_Mux`, `UL_SRC_MUX`, `UL2_SRC_MUX`, `DMIC0/1/2_MUX`, `Headset Volume`, `PGA1 Volume`, `PGA2 Volume` |
| aw883xx (per channel N) | `aw_dev_N_prof` (enum from the ACF), `aw_dev_N_switch` (Disable/Enable), `aw_dev_N_monitor_switch`, `aw_dev_N_rx_volume` |
| machine | `Ext_Speaker_Amp Switch`, `MTK_SPK_TYPE_GET`, … (Android-only helpers) |

Gotchas found in the source:

- **`Headset Volume` is inverted:** raw 0 = +8 dB, 8 = 0 dB, 18 = −10 dB (`DL_GAIN_8DB = 0` … `DL_GAIN_N_10DB =
  18`), but its TLV says 0 = −10 dB. Never give it to PipeWire as a hardware volume; the UCM sets a fixed level.
- `aw_dev_N_rx_volume` is attenuation in 1/8 dB (AW88394: 0 = 0 dB … 720 = mute); no TLV. Changing
  `aw_dev_N_prof` **resets it to 0 dB at the next stream start** (`aw883xx_device_start`: profile change clears
  `ctl_volume`). The test script primes with silence after a profile change, then attenuates.
- `PGA1/PGA2 Volume`: 0–4 = 0–24 dB analog.
- Jack: `mt6377_accdet_init` calls `snd_soc_card_jack_new("Headset Jack", …, NULL, 0)`, which creates **no ALSA
  kcontrol**, only an input device with `SW_HEADPHONE_INSERT`/`SW_MICROPHONE_INSERT` and buttons (KEY_MEDIA,
  VOLUMEDOWN/UP, VOICECOMMAND). PipeWire's UCM support only uses `JackControl` (kcontrols), so it can't see plug state.

## Android routing → ALSA sequences

`audio_device.xml` path names in quotes. The HAL also opens hostless "SPK_INIT" (`I2S3_HD_Mux Low_Jitter`,
`I2S3_Out_Mux Dummy_Widget`, then back to Normal) and sets `*_scenario` controls; neither is needed here.

**Speaker** (both AW88394, stereo): FE Playback_1, `PLAYBACK1_TO_I2S3` + `speaker_output_mode_music`.
`SPK_PATH_NO_ANA=yes`, so the MT6377 `speaker_output` (LOL) path is not used.
```
Enable:  I2S3_CH1 DL1_CH1=1, I2S3_CH2 DL1_CH2=1, I2S3_HD_Mux=Low_Jitter,
         aw_dev_0_prof=Music, aw_dev_1_prof=Music, aw_dev_0_switch=Enable, aw_dev_1_switch=Enable
Disable: (nothing; DAPM powers the amps down when the stream stops)
```
**Earpiece**: `RCV_OUT path="I2S3"`, `RCV_PATH_NO_ANA=yes`, "RCV_OUT_DEVICE_CTRL_PRE_PMU":
```
Enable:  (I2S3 routes as above), aw_dev_1_switch=Disable, aw_dev_0_switch=Enable, aw_dev_0_prof=Receiver
Disable: aw_dev_1_switch=Enable, aw_dev_0_switch=Enable, aw_dev_0_prof=Music
```
**Headphones** (3.5 mm): FE Playback_2 (the HAL uses DL1 with `PLAYBACK1_TO_ADDA_DL`; a separate FE lets speaker and
headphones be separate PCMs), "headphone_output":
```
Enable:  ADDA_DL_CH1 DL2_CH1=1, ADDA_DL_CH2 DL2_CH2=1, DAC In Mux='Normal Path',
         HPL Mux='Audio Playback', HPR Mux='Audio Playback', Headset Volume=9,9 (-1 dB; Android HS headset_pga=9)
Disable: HPL Mux=Open, HPR Mux=Open
```
**Built-in mic** (main, bottom, AIN0): FE Capture_1, `ADDA_TO_CAPTURE1` + "builtin_Mic_SingleMic":
```
Enable:  UL1_CH1 ADDA_UL_CH1=1, UL1_CH2 ADDA_UL_CH2=1, MISO0_MUX=UL1_CH1, MISO1_MUX=UL1_CH1,
         ADC_L_Mux='Left Preamplifier', PGA_L_Mux=AIN0, DMIC0_MUX=DMIC_DATA0, DMIC1_MUX=DMIC_DATA0, PGA1 Volume=4
Disable: MISO1_MUX=UL1_CH2, ADC_L_Mux=Idle, PGA_L_Mux=None, UL_SRC_MUX=AMIC, UL2_SRC_MUX=AMIC
```
"builtin_Mic_DualMic" (main + back mic as L/R): MISO1_MUX=UL1_CH2, ADC_R_Mux='Right Preamplifier', PGA_R_Mux=AIN2.
"builtin_Mic_BackMic" swaps MISO0/MISO1.

**Headset mic** (AIN1), "headset_mic_input":
```
Enable:  (Capture_1 routes), MISO0_MUX=UL1_CH1, MISO1_MUX=UL1_CH1, ADC_L_Mux='Left Preamplifier', PGA_L_Mux=AIN1
Disable: MISO1_MUX=UL1_CH2, ADC_L_Mux=Idle, PGA_L_Mux=None
```
**Idle** ("reset_device_setting"): `ADDA_UL_Mux=MTKAIF`; `LOL/HPL/HPR/RCV Mux=Open`; `ADC_L/R_Mux=Idle`;
`PGA_L/R_Mux=None`; `MISO0/1/2_MUX=UL1_CH1/UL1_CH2/UL2_CH1`; `UL_SRC_MUX=AMIC`, `UL2_SRC_MUX=AMIC`.

## UCM2 draft

`port/vegas/root/usr/share/alsa/ucm2/`:
- `conf.d/mt6835-mt6377/mt6835-mt6377.conf` → `MediaTek/mt6835/mt6377-aw88394/mt6835-mt6377.conf`. The ASoC
  driver/longname are both `mt6835-mt6377`, so both of alsa-lib's conf.d lookups hit this file.
- `init.conf` (BootSequence): the idle state, all FE interconnects (the MT8189 lesson: ACP opens every PCM before any
  EnableSequence and MediaTek DPCM FEs reject `hw_params` until routed), `I2S3_HD_Mux Low_Jitter`, gains, amps in
  Music/Enable, `aw_dev_2_switch Disable` last.
- `HiFi.conf`: Speaker (prio 100) and Earpiece (50) on Playback_1, conflicting; Headphones (90) on Playback_2; Mic
  (100) and Headset (50) on Capture_1, conflicting. PCMs via `${find-device:...regex='^Playback_1 '}`. No
  `JackControl` (none exists), so Speaker outranks Headphones.
- Parse-checked on the host with `alsaucm` against a scratch copy (PCMs substituted): verb HiFi, 5 devices. The
  cset values themselves are only checked against the source.
- Not upstreamable as is: `mt6835-mt6377` is MediaTek's generic card name. Another MT6835 + MT6377 phone with
  different amps would match the same file. Upstream would need a board condition, e.g. `ControlExists
  aw_dev_2_switch`, or a card long name set from the DT model.

## Open questions

- **aw_dev_2 (AW88166 at 6-0037).** Its profiles are `Music/Hac/Bypass`, and the HAL touches `aw_dev_2_switch/prof`
  around HAC (hearing-aid) mode. It shares I2S3, so with its default Music profile it would play along. The draft
  keeps it disabled. Is it a telecoil driver, and is its default off on Android? Check `aw_dev_2_*` after the card
  binds, before any playback.
- Default profile/switch states after probe, and whether `aw_dev_N_prof` lists exactly the ACF names (the UCM uses
  the names `Music`, `Receiver`).
- Which of aw_dev_0/1 is left vs right? Both play I2S3 L/R according to the ACF; listen, or record per channel.
- Speaker calibration: Android stores a per-unit `cali_re` (`/sys/.../6-0034/cali_re`, `aw883xx_cali`,
  `MTK_HAL_SET_AW_CALI_SUPPORT`). Without it the driver uses the ACF/bin default Re. That's fine at low level, but
  find the persisted value (likely in `/mnt/vendor/persist` or nvram) before using full volume.
- Loudness: without BesLoudness/SKTune the speaker may sound quieter or thinner than on Android. Compare by ear and,
  if needed, add a PipeWire filter-chain EQ (the Chromebook has the same open item with CRAS's DSP).
- `I2S3_HD_Mux Low_Jitter` vs Normal: the HAL leaves SPK_INIT in Normal after its turnoff, but the smart-amp param
  says APLL is needed. If playback underruns or clicks, try Normal.
- Mic gain: Android's 34 dB = 24 dB analog (PGA 4) plus ~10 dB digital (HW gain block, not routed here). Expect
  low levels; check RMS, then consider `HW_GAIN2` routing or a software gain.
- Is the jack exposed at all to Omarchy? Only as the evdev device above. Decide on a watcher vs manual sink choice.
- `scp.ko` side effects (first Linux load), and whether loading `ccci_fsm_scp`/`mtk-vow` is ever needed (not for
  this card).
- The test hard-codes nothing about PCM numbers, but the predicted numbering (Playback_1=0, Playback_2=2,
  Capture_1=10) should be confirmed in `/proc/asound/pcm`.
